# TransNote 产品愿景与边界（Agent 必读）

> 每次动手前先读一遍。与 AGENTS.md 冲突时，以本文件的产品边界为准。
> 本文件是「为什么做这个项目」的权威来源，防止 agent 按自己的想象加功能。

## 一句话定位

**类 Notion 的块级协作平台（文档 + 待办看板），核心差异化 = AI 驱动的 Word ↔ 待办看板双向转换，且全程逐条可追溯。**

## 核心卖点（项目存在的理由）

**AI 双向转换 + 可追溯** —— 上传 .docx 自动变成带负责人/截止/优先级的待办看板；看板一键导出为排版良好的 .docx；**每条任务都带原文段落引用，可跳回出处**；低置信项强制人工校对，不盲目自动化。

这是主流工具（Notion / 飞书 / 钉钉）没有做透的空白点：它们有文档与任务，但没有「Word 与看板之间的 AI 双向无损转换 + 追溯」。**任何功能都不得破坏「转换可追溯 + 人工校对门」这条主线**（对应 ADR-4/5）。

## 边界（不做清单）

| 不做 | 原因 |
|---|---|
| IM 聊天 / 邮件 / 日历应用 | 定位是文档与任务协作，非通讯 |
| 表格数据库视图（Notion database 式） | MVP 范围外，Phase 2+ 视需求再议 |
| 模板市场 / 评论 / 模板分享社区 | 未拍板前一律不引入，避免范围蔓延 |
| 移动端完整编辑 | Phase 3 再做，MVP 只保留 API 契约 |
| 多租户 SaaS 管理后台 | MVP 面向工作区（workspace）模型，单机/私有部署优先 |

## 决策准则

1. 转换准确率 > 功能数量：宁可少功能，不可让转换结果不可信。
2. 方案优先、按需生成：默认先出方案文档等用户拍板，不擅自实现（见 milestone-flow.md）。
3. 规则优先于 LLM：能用正则/结构确定的（日期、@负责人、勾选项）不烧 token。
4. 最小改动：用户没要求的重构/优化不做。
